# CLAUDE.md

`activities-widget` — the "Upcoming activities" card on the Uspacy portal (React 18 + MUI): CRM tasks of today and
tomorrow, a countdown to the next one, each item links to `/crm/tasks/:id`. A webpack Module Federation remote
(`UspacyActivitiesWidget`, exposes `./app`), served from GitHub Pages. `README.md` is the marketplace boilerplate —
ignore it; `./settings` (`components/Settings`) returns `null` and nothing loads it.

## Setup

```sh
export NPM_AUTH_TOKEN=<github token>   # REQUIRED: .npmrc interpolates it; a real token is needed for @uspacy/* packages
yarn install --frozen-lockfile         # Yarn 1 (yarn.lock); `prepare` installs the husky pre-commit hook
yarn dev                               # webpack dev server on http://localhost:8080 (opens the browser), remoteEntry.js
```

- Node 22.23.4 — pinned literally in `.github/workflows/pages.yml`. No `.nvmrc`.
- No `.env` is needed: the code reads only `NODE_ENV` (`dotenv-webpack` stays in the config but has nothing to load).
- The standalone page on :8080 (`src/bootstrap.tsx` + `public/index.html`) **crashes on load**: the local
  `@uspacy/store` 0.0.185 uses the removed object form of `extraReducers`, `@reduxjs/toolkit` 2.x throws. Do not fix it —
  always test inside the container, which supplies its own store, SDK session and `userSettings`:
  1. `yarn dev` here (port 8080).
  2. In `../container-frontend/src/components/ActivityWidget/index.tsx` temporarily set
     `url: 'http://localhost:8080'`, then `yarn start` there (port 3000; it logs in with `REACT_APP_AUTH_EMAIL` /
     `REACT_APP_AUTH_PASSWORD` from its `.env`, which picks the portal).
  3. Open `http://localhost:3000/newsfeed` — the widget is in the right column, under "Birthdays". Reload after changes.
  4. Revert the container file and `public/service-workers.js` (regenerated by `yarn start`) — never commit them.
- Expected noise in that setup: `Unsatisfied version ... of shared singleton module` warnings and
  `ERR_CONNECTION_REFUSED` for remotes on ports 3002/3004 that are not running.

## Verification

Run before every commit; all must exit 0:

```sh
yarn eslint          # eslint over src/, --max-warnings=0 (~2s); prettier runs inside eslint
npx tsc --noEmit     # type-check (strict); `resolutions` pins @types/react 18 — without it bootstrap.tsx fails
yarn build           # production build -> dist/ (remoteEntry.js + static/js); asset-size warnings are expected
```

- `yarn build` uses `babel-loader` only — it does **not** type-check and does not run ESLint, so a green build proves
  nothing about types. ESLint runs inside `yarn dev`.
- `yarn eslint:fix` autofixes formatting and import order.
- Pre-commit (husky + lint-staged) runs `npm run eslint` — over the whole `src/`, not only staged files — on staged
  `*.{ts,tsx,js}`. Never bypass it.
- No tests and no test runner. Do not add test tooling unless asked.
- **There is no CI on PRs** — the only workflow is `pages.yml` (deploy on push to `main`), so the three commands above
  are the only gate.

## Conventions

- **Merge to `main` = live in production for every portal at once.** `pages.yml` runs `npm install && npm run build`
  and pushes `dist/` to the `gh-pages` branch; `../container-frontend` (`src/components/ActivityWidget/index.tsx`,
  rendered on `/newsfeed`) loads `https://uspacy.github.io/activities-widget` at runtime — no version, no stage, no
  rollback except a PR that reverts the change. If the remote fails to load, the container silently renders nothing.
- CI installs with **npm**, not yarn (`package-lock.json` is gitignored), so production may resolve different
  versions than `yarn.lock`, and yarn `resolutions` do not apply there. Intentional — do not switch it to yarn.
- **Contracts with `container-frontend` — do not change without the developer's explicit approval:**
  - `appName = 'UspacyActivitiesWidget'`, `filename: 'remoteEntry.js'`, exposed key `./app`, output dir `dist`,
    the Pages URL. Renaming any of them breaks the widget on every portal.
  - `App` props: only `userSettings` (the portal's settings; only `lang` is used).
  - The `shared` block in `webpack.config.js`: react, react-dom, MUI, emotion, `@uspacy/store`, `@uspacy/sdk`,
    `@reduxjs/toolkit`, `react-redux` are singletons taken from the **host's** versions (much newer than ours).
    `Uspacy.createInstance()` uses the host's SDK and session — a method missing in the host's `@uspacy/sdk` breaks
    the widget only on the portal, never in tsc.
  - `.github/workflows/pages.yml`, `.npmrc`.
- Where logic lives: everything is in `components/ActivitiesWidget/index.tsx` — fetch
  (`crmTasksService.getTasksWithFilters`, `start_time` from today 00:00 to tomorrow 23:59, `list: 1000`), task →
  `Activity` mapping, grouping into `today` / `tomorrow` / `next`, icons by type/priority. Styled parts in
  `ui/primitives.tsx`, enums in `types.ts`. Timestamps are unix **seconds** (`* 1000` everywhere).
- `AddButton` and the `addActivity` key are kept on purpose: the button is commented out until a "create task" route
  exists. Do not delete them.
- TODO (open product questions — do not "fix" without the developer's decision):
  - the `next` group is always empty: only today + tomorrow are fetched;
  - the request has no `responsible_id` filter — all tasks visible to the user are shown, not only theirs;
  - `formatTime` always uses `uk-UA` and ignores `userSettings.timeFormat` / `timezone`;
  - items are plain `<a href>` → a full page reload instead of the host router.
- i18n is local JSON only (no Locize or other sync), edited directly in this repo:
  `src/locales-widget/<lng>/translation.json` × 6 (`uk`, `en-US`, `de`, `es-ES`, `pl`, `pt-BR`), fallback `uk`.
  Add every new key to all six.
- **Keep the own i18next instance** (`src/i18n.ts`: `createInstance()`, passed only via `I18nextProvider` in `App`).
  `i18next` and `react-i18next` are shared with the host and other remotes, so `import i18n from 'i18next'` is one
  global object per page: this widget used to load its locale files into it and broke `uspacy-birthday-widget`
  (rendered next to it). Do not go back to the default export and do not add `initReactI18next` — it calls `setI18n`
  on the host's `react-i18next` and replaces its global instance.
- **`main` changes only through a PR** — never merge or push into `main` locally. Rollback = a PR that reverts the
  original one (GitHub "Revert" button); never a reset or force-push of `main`.
- **Never commit or push without the developer's explicit confirmation** — ask every time, even after earlier approvals.
- **Never force-push** (`--force`, `--force-with-lease`, `+refspec`). If a push is rejected, stop and ask the developer.
- **Always commit the normal way.** Never skip or disable git hooks: no `--no-verify` / `-n` (incl. combined flags like
  `-nm`), `HUSKY=0`, `-c core.hooksPath=...` or similar. If a hook fails, fix the cause; if you cannot, stop and ask.
- **Git naming.** Branches: `feat/<ticket>_<short_name>` or `fix/<ticket>_<short_name>`, where `<ticket>`
  is the Uspacy task number. PR title: `[<ticket>]: <short summary of the PR>`; take the number from the
  branch name, and if it is not there, ask the developer. Commit message: a short description of what this
  specific commit does, with no ticket prefix.
- All PR titles and descriptions, commit messages, and replies to review comments are written in English, regardless of the language of the prompt or the conversation.
